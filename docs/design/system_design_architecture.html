01 / System Overview

Executive System Overview

The Harbor & Environmental Mass Spectrometry (HEMS) Workshop web platform is a hybrid static-dynamic research platform. It acts as both the public institutional portal for the biennial international conference and the authoritative research repository archiving over 25 years of mass spectrometry proceedings (1999–2025) comprising 1,590 files (1.68 GB).

15 Workshops
Spanning 1999 to 2025 with complete plenary, talk, poster, and attendee catalogs.
1,590 Proceedings
High-resolution slide presentations, abstracts, programs, and audio/video records.
Dual-Mode Architecture
Decoupled local developer workbench + high-speed static CDN deployment on Firebase.

04 / Layout & Routes

Layout & Page Route Hierarchy

The application uses the Next.js 16 App Router structure located in src/frontend/src/app/. Routes are grouped logically into public marketing pages, dynamic proceedings viewers, authenticated portals, and the developer manager workbench.

Public Core Routes
  • / — Landing page, featured highlights, countdown
  • /archive — Multi-year catalog & deep search portal
  • /archive/[year] — Dynamic workshop proceedings viewer
  • /about — History, mission, and workshop committee
  • /accommodations — Venue and lodging details
  • /call-for-papers — Abstract deadlines & submission criteria
  • /corporate-sponsorship — Tiers & historical sponsor gallery
  • /registration — Conference registration & badge pickup
  • /student-awards — Student presentation grant guidelines
Role-Gated Portals & Workbench
  • /auth — Firebase Authentication (Email/Password & Google)
  • /(portal)/admin — User RBAC roles, whitelist manager
  • /(portal)/board — Executive committee meeting archives
  • /(portal)/reviewer — Double-blind abstract scoring system
  • /manager — Local Workshop Manager workbench (dev-only)
  • /api/manager/* — Local API handlers (serve, check, upload)
05 / Research Archives

Proceedings Engine & Dual-Path Architecture

The archive engine (src/frontend/src/app/archive/[year]/page.tsx) generates complete proceedings interfaces for all 15 workshops using pre-rendered Static Site Generation (generateStaticParams).

Dual-Mode Asset Resolution Pipeline

To enable zero-cloud local offline pair programming without sacrificing production CDN speed, the system resolves assets dynamically:
Local Development Mode

Streams directly from local_data/proceedings/ via /api/manager/serve?file=.... Provides instantaneous PDF viewing and local preview rendering without hitting GCS.

Production CDN Mode

Links resolve directly to Google Cloud Storage multi-region bucket: https://storage.googleapis.com/hems-workshop-archives/proceedings/....

06 / Local Developer Tooling

Workshop Manager Workbench (/manager)

The Workshop Manager is a specialized local administrative GUI located at http://localhost:3000/manager. It empowers the human organizer or AI agent to curate proceedings without manual JSON editing.

Key Capabilities
  • Drag & Drop Ingestion: Drag any presentation or abstract PDF directly into session drop zones.
  • Live Status Health Check: Real-time polling indicates whether the file exists locally and on GCloud.
  • Instant Previews: Generates first-page PNG previews and extracted abstract text summaries.
  • 301 Redirect Control: Checkbox enables "Legacy URL for 301 Redirect only" for un-downloaded items.
  • Corporate Registry Sync: Real-time corporate sponsor dropdown with instant logo preview and affiliation.
Production Build Isolation

Because the Workshop Manager utilizes Node.js server routes (fs, child processes, local file writing), it is strictly isolated from production:

node scripts/build-prod.js
↳ Temporarily isolates /manager & /api/manager
↳ Executes Next.js static compilation
↳ Restores manager routes for local dev
07 / Cloud Architecture

Backend & Cloud Infrastructure

Firebase Functions v2 & Event Triggers

Located in functions/src/index.ts running on Node.js 22. It deploys second-generation Firestore event triggers:

// Triggered on new Firebase Auth user creation
export const onUserCreate = functions.auth.user().onCreate(async (user) => {
  // 1. Check whitelist collection in Firestore
  // 2. Assign custom claims: { role: 'admin' | 'board' | 'reviewer' }
  // 3. Create initial profile document in users/{uid}
});
Cloud Storage Bucket

Bucket Name: hems-workshop-archives

Path Structure:

  • • /proceedings/{ordinal}/{session}/{file}.pdf
  • • /sponsors/{logo_file}.png
Search Engine Indexing

Deep full-text slide indexing is executed via src/frontend/scripts/index-pdf-contents.js, compiling 7,244 searchable text chunks into public/mock-pdf-chunks.json and pushing to Algolia.

08 / Access Control

Security & Role-Based Access Control (RBAC)

Admin
Full system control, role granting, workshop edit
Board
Executive minutes, financial logs, committee governance
Reviewer
Blind abstract rubric scoring, submission evaluation
General
Public proceedings streaming, registered attendee access

Daily IP & User Download Quotas

To prevent scraping bots from mass-downloading HEMS intellectual property, Firestore security rules enforced in firestore.rules limit anonymous access and rate-limit logged downloads to a daily ceiling, logging telemetry in downloads_log/{id}.

09 / Schemas & Registries

Canonical Data Registries

master_workshops.json src/frontend/src/data/master_workshops.json

Authoritative master array defining all 15 workshops. Feeds the Workshop Manager and generates individual archive year files.

corporate_registry.json src/frontend/src/data/corporate_registry.json

Database of all 52 participating corporations, historical sponsor dates, active URLs, and normalized logo filenames.

permalink_registry.json docs/registries/permalink_registry.json

Exact mapping table for 301 legacy redirects ensuring legacy scientific paper citations route cleanly to modern paths.

pdf_seo_registry.md docs/registries/pdf_seo_registry.md

Deep academic metadata registry containing title, abstract text, presenter, and keywords for search engine discovery.

10 / Developer Handbook

Developer & AI Agent Quickstart

1. Run Local Development Server 
cd src/frontend
npm run dev
# Main Web App:         http://localhost:3000
# Workshop Manager:     http://localhost:3000/manager
2. Execute Production Static Build 
cd src/frontend
npm run build
# Compiles search indices and prerenders 36+ SSG static routes to src/frontend/out/
3. Sync Local Assets to Google Cloud Storage 
cd src/frontend
npm run push-to-live
# Pushes any newly dropped local proceedings from local_data/proceedings to GCS
4. Deploy Cloud Functions 
cd functions
npm run build
firebase deploy --only functions

Agile Release Train (ART) Operating Governance

When developing with pairing agents: @dev implements inside src/; @qa tests inside tests/; @ops manages infrastructure, Git, and .gitignore; @arch authors architecture plans in docs/plans/; @brand oversees aesthetics in docs/design/ governed by .agents/config/design/brand-guidelines.md; and @bo serves as the supreme authority.
