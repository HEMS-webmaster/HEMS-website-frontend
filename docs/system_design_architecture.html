Executive System Overview

The Harsh-Environment Mass Spectrometry (HEMS) Society, Inc. platform (hems-workshop.org) is an ultra-low-cost, Always-Free-governed ($0.00/mo steady-state standing compute on Firebase Blaze + Google Workspace for Nonprofits) hybrid static-serverless architecture. The workshop series first convened in February 1999 at the University of South Florida (USF) Center for Ocean Technology in St. Petersburg, FL, and the Society incorporated as an all-volunteer Florida 501(c)(3) nonprofit in 2008 (convening its first post-incorporation meeting—the 7th Workshop—in Santa Barbara, CA in 2009). The platform operates both as the permanent Google-Scholar-indexable digital archive spanning 15 workshops (1999–2025; 436 cataloged works; 1,590 files / 1.68 GB) and as the full-cycle operational committee workbench for the biennial symposium—currently staged for the 16th HEMS Workshop (September 2027).

02 / Architectural Decision Records — Why The System Works This Way

Key Design Decisions & Institutional Reasoning

An all-volunteer nonprofit scientific society has very different constraints from a venture-backed SaaS company: years between workshops see near-zero traffic (requiring $0.00/mo idle cost and zero server patching), committees rotate officers biennially (requiring non-technical self-service controls and strict separation of duties), and research citations must stay stable for decades. Every major technical choice reflects those constraints:

ADR-01 • Static Export Frontend + On-Demand Cloud Functions v2

Choice: Build src/frontend with output: 'export' onto Firebase Hosting CDN rather than running an always-on Next.js SSR container, paired with 14 stateless Cloud Functions v2 (minInstances: 0, maxInstances: 2–5).
Why: Eliminates idle VPS/Cloud Run billing (remains inside Blaze Always-Free quotas between workshops), removes Node server OS patching obligations for volunteer webmasters, and confines privileged server secrets cleanly to Stripe/Postmark/Sheets endpoints.

ADR-02 • Separate Port-4000 Local Workbench (tools/manager)

Choice: House file uploads, JSON editing, sponsor ingestion, Python preview generation, and gsutil rsync inside tools/manager instead of src/frontend.
Why: Next.js output: 'export' rejects filesystem API routes, and keeping ingestion strictly offline on a maintainer's workstation prevents arbitrary file/command endpoints from ever shipping to the public web. Historical JSONs in Git + build-prod.js act as a Zod-verified publishing gate.

ADR-03 • Dual Archive Path: Public GCS URLs + Gated Website Downloads

Choice: Keep direct storage.googleapis.com/hems-workshop-archives/... URLs publicly readable for ScholarlyArticle JSON-LD while gating interactive UI clicks through DownloadGate.tsx (30/day cap).
Why: Google Scholar & academic crawlers require unauthenticated direct PDF URLs with <meta> / JSON-LD metadata to index 25+ years of papers. Meanwhile, the passwordless UI gate captures verified researcher interest, enables voluntary newsletter opt-in, and the $7.50 Pub/Sub circuit breaker caps worst-case egress exposure.

ADR-04 • 53-Key In-App Control Center (Retiring Inbound Sheet CSV)

Choice: Retire live Google Sheet CSV config fetching in favor of Firestore /admin/workshop-settings (keeping outbound Sheets API v4 append only for paid registration logs).
Why: Public Google Sheet CSV edits had zero validation, broke on unescaped dollar commas ("$1,500"), pushed typos immediately to visitors, and had no rollback. The Control Center adds typed checks, Draft/Live isolation, 7–30 day zero-login ?preview= review links for Board sign-off, and 1-click version rollback—while bundled upcoming_workshop.json renders frame-0 instantaneously with zero flash.

ADR-05 • Postmark Zero-Tracking & Cookie-Free Telemetry

Choice: Send all bulk/transactional email via announcements@mail.hems-workshop.org with TrackOpens: false, TrackLinks: "None", plus first-party salted-SHA256 telemetry.
Why: HEMS attendees predominantly work at national labs (.gov), universities (.edu), and defense agencies (.mil) whose mail gateways strip or quarantine redirect-wrapped tracking URLs and spy pixels. Direct ?src=<slug> URLs preserve full deliverability and campaign attribution with zero raw IP storage or invasive cookie banners.

ADR-06 • Passwordless-First Two-Tier Login + Verified-Email RBAC Gate

Choice: Offer OAuth + 1-click Email Magic Links for quick paper downloads, while requiring hasVerifiedAuthEmail() in Rules, Functions, and UI before granting any whitelisted role.
Why: Scientists balk at inventing yet another password just to read a 2005 PDF, whereas officers need ironclad protection: someone creating an unverified Email+Password account typed with an officer's email address must NEVER inherit Board, Treasurer, or Admin rights until link verification succeeds.

ADR-07 • Client-Side PDF/OOXML Generation & Opt-In Local Search Index

Choice: Generate IRS receipts, participant lists, and Schedule PDF + genuine Word .docx files directly in browser TypeScript, and pre-build archives-index.json + opt-in mock-pdf-chunks.json.
Why: Avoids paid search SaaS (Algolia) and server-side Puppeteer/LibreOffice containers. Producing native ZIP-packaged OOXML .docx lets committee chairs polish talk wording in Word right before print without breaking Math/Greek characters.

ADR-08 • Strict 6-Portal Separation of Duties

Choice: Do not auto-cascade roles (Operations ≠ Treasurer ≠ Board ≠ Admin, except Reviewer inherits for Board/Admin only where intended; webmaster permanently retains Admin).
Why: Volunteer nonprofit governance requires clean boundaries between who touches Stripe payouts/refunds (Treasurer), who runs check-in/email blasts (Operations), who stores legal minutes (Board), who reviews blind abstracts (Reviewer), and who flips live website state (Admin).
