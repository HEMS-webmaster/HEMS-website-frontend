Read First: 8 Critical Pitfalls Uncovered on Your Live GoDaddy Zone

Must Review Before Editing DNS
1. Sucuri / GoDaddy Website Security WAF IP (192.124.249.10) Your live @ A record currently points to 192.124.249.10, which is GoDaddy's Website Security Firewall (Sucuri WAF) proxy—not an ordinary server! If GoDaddy Website Security WAF is left active, it can overwrite your DNS edits or block Firebase's Let's Encrypt SSL verification. Disable/bypass Website Security WAF for hems-workshop.org before swapping the A record.
2. Canonical Direction: www MUST Be Primary (Not Apex) Every <link rel="canonical">, sitemap.xml entry, JSON-LD article, and llms.txt link in our codebase uses https://www.hems-workshop.org/. In Firebase Hosting, add www.hems-workshop.org as the Primary Domain, and set hems-workshop.org to Redirect to www.hems-workshop.org—never the reverse, or Google will see canonical redirect loops!
3. NEVER Delete MX or google-site-verification Your GoDaddy zone currently has MX → smtp.google.com (Priority 1) powering @hems-workshop.org email and TXT → google-site-verification=FsDtU... verifying Google Search Console. Leave both untouched, and do NOT change GoDaddy Nameservers (ns33/ns34.domaincontrol.com).
4. Check GoDaddy's Hidden "Forwarding" Card at Page Bottom At the bottom of GoDaddy's DNS page is a separate Forwarding panel (Domain / Subdomain forwarding). Make sure GoDaddy Forwarding is OFF—if turned on, GoDaddy injects a hidden parked A record that breaks HTTPS certificates. Let Firebase Hosting handle the HTTPS 301 redirect cleanly.
5. Firebase Auth "Authorized Domains" (Google/Microsoft Login) Both www.hems-workshop.org and hems-workshop.org MUST appear under Firebase Console → Authentication → Settings → Authorized domains. If missing, users clicking Sign In with Google/Microsoft to download archive PDFs will get auth/unauthorized-domain.
6. Expect a 15–45 Minute SSL Certificate Minting Window Because your current GoDaddy A record has a 30-second TTL, traffic switches to Firebase within minutes—but Google's automated SSL certificate takes 15–60 minutes to mint once DNS resolves. Browsers may briefly show ERR_SSL_VERSION_OR_CIPHER_MISMATCH during that window. Do not panic or revert DNS; wait ~30–45 minutes (cut over in the evening).
7. Live Email Bug Found: Old GoDaddy SPF Hard-Fail (-all) Your live DNS uses Google Workspace (smtp.google.com), yet your SPF TXT record still says v=spf1 include:secureserver.net -all! That tells .gov/.edu mail servers to reject Google Workspace mail. Edit that existing TXT record in-place to v=spf1 include:_spf.google.com ~all (never create two separate v=spf1 records!).
8. Keep Old GoDaddy Hosting Un-Cancelled for 7–14 Days All 1,590 HEMS proceedings PDFs and slide previews already live on Google Cloud Storage (storage.googleapis.com/hems-workshop-archives), so zero archive PDFs depend on GoDaddy hosting. Still, wait 1–2 weeks before cancelling the legacy hosting plan as a safety backup.

Phase 1 — Pre-Flight Backup & Fresh Firebase Deploy (Before Touching GoDaddy)

~5 Minutes

In GoDaddy → Domains → hems-workshop.org → DNS → DNS Records, click the More ▾ menu above the records table and select Export Zone File (Unix/Windows) (and take a quick screenshot). This gives you an instant 30-second rollback reference.

Ensure the latest build (with SEO JSON-LD, llms-full.txt, GA4 G-F06RZ8L5CR, and Search Console links) is deployed to https://hems-workshop.web.app before switching DNS: 

npm --prefix src/frontend run build && npx firebase-tools deploy --only hosting --project hems-workshop

In your GoDaddy product dashboard, check Website Security & Backups → Firewall (WAF). If active on hems-workshop.org (which set the 192.124.249.10 A record), disable WAF proxy forwarding. Also verify the Forwarding section at the bottom of GoDaddy DNS says Off.

Phase 2 — Register Both Domains in Firebase Hosting (Order Matters!)

~5 Minutes

Open Firebase Console → Hosting and click Add custom domain. Enter www.hems-workshop.org Copy. Leave "Redirect to another domain" UNCHECKED, click Continue, and keep the DNS values shown on screen.

Click Add custom domain again. Enter hems-workshop.org Copy, CHECK "Redirect to another domain", and choose www.hems-workshop.org as the destination. Note the required TXT and A record values Firebase displays (Firebase also warns if an old A record like 192.124.249.10 must be removed).

Open Firebase Console → Authentication → Settings → Authorized domains and confirm both www.hems-workshop.org and hems-workshop.org are in the list (click Add domain right now if either is missing so Google/Microsoft sign-in works at zero-minute cutover!).

Phase 3 — Apply DNS Records in GoDaddy & Trigger SSL Minting

~10 Minutes Active + 15–45 Min SSL Wait

In GoDaddy DNS, click Add New Record → Type: TXT, Name: @, Value: hosting-site=hems-workshop (or exact string shown in Firebase), TTL: 1/2 Hour (or Custom 600 seconds). Leave your existing google-site-verification=... TXT record untouched.

Delete the A record pointing @ to 192.124.249.10. Add a new A record with Name: @ and Value: 199.36.158.100 (matching Firebase's exact prompt). Confirm no other @ A or AAAA records exist.

Edit the existing www CNAME row (currently pointing to hems-workshop.org) to point to hems-workshop.web.app Copy (or if Firebase shows an A record for www, delete the www CNAME and add the www A record 199.36.158.100).

Click Edit on the existing TXT row v=spf1 include:secureserver.net -all and replace its value with v=spf1 include:_spf.google.com ~all Copy. Save. Confirm there is only one v=spf1 TXT record in the table.

Return to Firebase Hosting and click Verify on both www.hems-workshop.org and hems-workshop.org. Wait 15–60 minutes while Google provisions the free Let's Encrypt TLS certificates until both badges turn green (Connected). You can verify live DNS propagation from Windows PowerShell anytime: 

Resolve-DnsName www.hems-workshop.org ; Resolve-DnsName hems-workshop.org -Type A

Phase 4 — Post-Cutover SEO, Analytics & Smoke-Test Verification

~10 Minutes Once SSL Is Green

Test in an Incognito browser window: http://hems-workshop.org, https://hems-workshop.org, and http://www.hems-workshop.org should all 301-redirect cleanly with a valid padlock to https://www.hems-workshop.org/.

Visit https://www.hems-workshop.org/archive/2025/ — hover a Slide PDF and an Abstract PDF to verify preview cards, sign in via Google/Microsoft to test a PDF download, and confirm /llms.txt, /llms-full.txt, /archives-index.json, and /sitemap.xml all load cleanly.

Open Google Search Console → select your hems-workshop.org property → Sitemaps → submit https://www.hems-workshop.org/sitemap.xml Copy. Then use URL Inspection on https://www.hems-workshop.org/ and https://www.hems-workshop.org/archive/ and click Request Indexing.

Open Google Analytics → Admin → Data Streams → confirm the Web Stream URL is set to https://www.hems-workshop.org. Browse two public pages on your phone or an Incognito window and confirm 1 active user lights up in Reports → Realtime.

Send a test email from an external Gmail/institutional account to webmaster@hems-workshop.org (and reply back) to confirm 100% uninterrupted Google Workspace mail delivery and clean SPF: PASS headers.
